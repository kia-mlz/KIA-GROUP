# معماری پنل مدیریت کیا

پنل مدیریت یک اپلیکیشن مستقل درون apps/group/src/app/admin است. مسیرهای عمومی
پلتفرم، داده و Permissionهای خود را با دپارتمان‌ها مخلوط نمی‌کنند.

## مرزها

~~~text
/admin
├── مرکز کنترل                         → آمار، هشدارها و فعالیت‌ها
├── /departments                       → انتخاب فضای کاری
├── مدیریت پلتفرم                      → کاربران، نقش‌ها، پشتیبانی و پیام‌ها
├── مالی و فروش                        → سفارش، پرداخت، کیف پول و تخفیف
└── کنترل و سیستم                      → تحلیل، ممیزی، تنظیمات و امنیت

/admin/academy                         → فقط ابزارهای آکادمی
/admin/events                          → فقط ابزارهای ایونت
/admin/{work,material,community,labs}  → فضای کاری هر دپارتمان
~~~

AdminLayoutClient تنها مالک chrome پنل است: مسیر فعلی را به یک فضای کاری
تبدیل می‌کند، ناوبری مناسب را نمایش می‌دهد و هر آیتم را با ماتریس دسترسی
صادرشده از سرور فیلتر می‌کند. هیچ Permissionی در کلاینت مشتق یا ساخته نمی‌شود.

## منبع حقیقت

| دغدغه | منبع حقیقت |
| --- | --- |
| رنگ و هویت دپارتمان | @kia./brand |
| نقش‌های سیستمی و ماتریس دسترسی | @kia./permissions |
| دسترسی مؤثر مدیر | AuthUser.adminPanelAccess از API |
| کنترل دسترسی Endpoint | AdminAccessGuard و @AdminAccess |
| عملیات حساس | AdminAuditService |
| فرمت تاریخ، عدد و پول | LanguageProvider |

## APIهای عملیاتی موجود

تمام آیتم‌های فعال پنل به endpointهای واقعی apps/api/src/group/admin متصل
هستند: آمار، کاربران و نقش‌ها، دوره/درس، آزمون، رقابت/چالش، سفارش/پرداخت،
تخفیف/کیف پول، تیکت/پیام، تنظیمات و Audit.

فضاهای Work، Material، Community و Lab هنوز API مدیریت اختصاصی ندارند؛ تا
زمانی که مدل داده، guard و endpoint واقعی آن‌ها ساخته نشود، نباید برایشان
دکمه یا شمارنده‌ی ساختگی اضافه شود. صفحه‌ی فعلی این وضعیت را صریح نمایش
می‌دهد.

## الگوی افزودن یک ماژول دپارتمانی

1. مدل Prisma و migration غیرمخرب را اضافه کنید.
2. یک بخش دسترسی در @kia./permissions تعریف کنید و migration داده‌های
   adminAccess را انجام دهید.
3. endpointهای /api/admin/department/resource را با JWT، Roles،
   AdminAccessGuard، DTO و ثبت Audit بسازید.
4. یک مسیر زیر /admin/department و یک آیتم در registry دپارتمان ایجاد کنید.
5. UI را فقط پس از اتصال کامل به endpoint واقعی وارد navigation کنید.
6. برای permission، validator، service و گردش اصلی E2E تست اضافه کنید.

## UX و دسترس‌پذیری

- Ctrl/Cmd + K، ناوبری صفحه‌ها و جست‌وجوی واقعی کاربر را باز می‌کند.
- تغییر مسیر فوکوس را به محتوای اصلی می‌برد.
- منوی موبایل Drawer و پنل بزرگ Sidebar است.
- کلیه controls دارای نام قابل‌دسترسی و focus ring هستند.
- motion با prefers-reduced-motion کاهش می‌یابد.
